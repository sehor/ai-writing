## 重现与数据隔离

在项目根目录逐档运行；执行器有短时限时不要把三档合成一个调用：

```powershell
rtk proxy node e2e/longform-benchmark.mjs --size small
rtk proxy node e2e/longform-benchmark.mjs --size medium
rtk proxy node e2e/longform-benchmark.mjs --size large
```

前端目录 `rtk pnpm test:perf` 运行 small；`rtk pnpm test:perf:full` 串行运行全部三档。只测后端时，在 backend 目录执行：

```powershell
rtk proxy uv --cache-dir ../.tmp/uv-cache run --frozen --extra dev python -m scripts.benchmark_longform --size medium --repeats 5
```

Python 默认创建并清理临时目录。浏览器脚本通过既有 E2E harness 建立隔离数据库、随机端口和独立 Chromium；清理本次服务器、浏览器和临时数据。`--root` 只用于 harness 的空临时目录，非空目录直接拒绝，不覆盖已有数据库或作者文件。夹具通过仓库/DTO 批量构建合法的已接受状态，不运行后台派生任务；因此测量不包含写入整本作品的事务吞吐或真实模型费用。

文本由固定种子20260907生成，每场景2,000个合成中文字，带独立标识；3份正文修订、1个事实及3个知识状态。每10场景一章、20章一卷，每5场景一个Canon条目。卷/事实UUID可变，因此ZIP大小有少量波动；正文按场景顺序的SHA-256固定。恢复时校验全部当前正文哈希与完整修订数量，不以“请求成功”代替内容完整性。

|---|---:|---:|---:|---:|

机器：Windows10 19045，i5-9400F 2.90GHz，6逻辑核，31.94GiB内存；Python3.13.14、SQLite3.50.4、Node22.16.0、Chromium148.0.7778.96。视口1440×1000，没有CPU限速，使用Vite开发服务器而非生产构建。单机结果不是跨机器性能保证。

## 分层方法

后端每操作先预热1次，记录5次的中位和最大耗时；raw SQLite读取包含本地连接与行读取，repository层再含DTO转换。snapshot为最后场景的无cognition模块快照，不能推算真实模型时延。HTTP独立测量本机完整响应体耗时、字节数及Node JSON解析耗时，不与仓库时间相减声称得到纯序列化时间。

浏览器动作从真实UI开始，等待目标可见和两个动画帧；包含自动化定位/滚动等待。CDP记录主线程TaskDuration/LayoutDuration等，区分DOM成本和网络，不把总耗时减API耗时当作渲染时间。首次应用空壳加载和首次打开合成项目分别只记录1次；切项目是“合成项目→空项目→合成项目”往返，其他交互各5次。n=5的nearest-rank p95就是最大样本，样本不足以作总体p95/SLA；偶发20秒长尾原样保留。

Python内存采样单独执行，不混入时延样本；峰值RSS包含夹具/预热/采样阶段。浏览器仅记录采样时JS堆，不是完整浏览器进程峰值，不能据此证明没有DOM/native内存增长。

## 初始预算、硬约束与支持范围

本轮把**200场景、每场景2,000字、3份修订（共40万字/600修订）**作为初始交互参考档：同档同机中位场景切换≤200ms、项目往返≤2s、历史打开≤1s且5次最大≤1.5s、snapshot≤200ms、备份导出≤2s。预算来自当前实测并留有余量，是后续对比目标，不是宣称所有规模均已达标。999场景的场景切换和历史面板不满足该交互目标；只能说完整性已验证，不能笼统称为长篇流畅。

现有字段约束必须分别看待：场景/章节/卷的sequence为1–999，不是数据库总场景数最多999；时态场景位置为0–999。正文输入后端每条上限40,000个Unicode字符，前端maxlength按UTF-16计数，含emoji时两者计量不同。备份压缩包上限64MiB、解压总量256MiB、成员数10,000。不能把本次约2百万字且只有3份历史的恢复结果外推到999×40,000字或大量修订/附件。

实际HTTP断言：序号1000与40,001字写入都返回422，历史未增加；999档全部999场景/2,997修订都返回，没有列表静默截断。轻量测试另验证40,000字边界、非空目录拒绝和备份超预算明确报错，原数据不变。模型上下文的有界筛选是提示词策略，不是删除/截断作者存储文本。
