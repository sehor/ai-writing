# P1、P2 与长篇性能修复计划

日期：2026-09-08。状态：已实施并完成本机验收，详见 [修复结果](./FIX-RESULT-2026-09-08.md)。T1/T2 草稿修复、T3 测量、T4/T6/T7 性能优化及 T8 验收完成；T5 经实测判断无需本轮新增服务端分页，使用完整读取与有界前端显示。以下保留原计划作为范围与验收依据。来源：[复核报告](./RECHECK-2026-09-08.md)、[性能基线](../../performance-baseline.md)、[PERF-01/02](../../performance-followups.md)。

## 目标与范围

修复跨提案接受造成的草稿丢失、撤回编辑后旧缓存复活，并降低长篇项目历史面板、场景切换与项目切换的等待时间。

默认沿用 Vue/Pinia、FastAPI/SQLite 及既有本机存储格式，不预设新增依赖或数据库迁移。本计划只设计修复，不提交业务改动、发布远端任务或调用付费模型。性能目标针对现有合成夹具与同机协议；真实作者、低配机器的体验仍需另行验收。

执行顺序：**P1 → P2 → 性能复测定位 → PERF-01 → PERF-02 → 综合验收**。各步独立提交与回退；本轮未启用多代理编排。

## 1. P1：离开前选择保存或放弃，接受期间禁止切换

- [x] **T1：按用户要求简化交互并修复跨提案接受。**

分两小步：先完成 proposalDraft 的保存/放弃与提案切换，再接入场景、项目和离开编辑面板的统一保护。涉及 `frontend/src/stores/manuscript/proposals.ts`、`frontend/src/stores/proposalDraft.ts`、`frontend/src/components/manuscript/ManuscriptProposalWorkspace.vue`、`frontend/src/composables/useDirtyGuard.ts` 和 workspace 的切换入口；测试随各切片提交。只调整本次正文提案离开行为，不顺带改变所有领域表单。

实现约定：

- 离开有修改的正文提案时显示三个选择：**保存草稿并离开 / 不保存并离开 / 取消**。明确提示“不保存将丢弃本次未提交修改”。此处保存是本机草稿暂存，不等于接受 AI 提案或生成正式正文修订。
- 保存成功才切换，失败留在原编辑器；不保存则取消自动保存定时器、清理该提案缓存并重置编辑状态，然后切换；取消保持原文与选择。必须避免现有 `open()`、卸载和 flush 逻辑把刚放弃的内容再次暂存。
- 点击接受后，在请求及其必要刷新结束前禁用编辑、重复提交和所有会离开该提案的应用内切换入口，显示“正在接受，请稍候”；成功或失败后解除限制。页面关闭仍使用浏览器原生离开提示，不能承诺自定义三按钮关闭窗口。
- 回调保留最小防护：请求捕获目标 ID/scope、会话标识和快照；清理前确认仍是原编辑器及提交快照，否则跳过当前草稿清理和选择变更。保留此校验是为了处理程序性状态重置，不再以支持提交中任意切换为目标。

验收：

1. 保存并离开后重新打开可恢复修改；不保存后切回或刷新均不恢复已放弃文本；取消不切换。缓存故障不能伪装成保存成功。
2. 接受 A 期间不能从提案、场景或项目入口切到 B；请求失败/409 后可继续编辑或离开；B 原有缓存始终不受影响。
3. 延迟响应测试中强制重置编辑器，回调也不清理新 scope；正常接受只产生既有规定的正式修订。无需扩展为通用异步事务框架。

验证：真实 Pinia + deferred fetch 行为测试；`pnpm test:unit`、`pnpm build`；浏览器覆盖离开三选项及接受期间切换被阻止。请求延迟使用可控响应，不使用固定 sleep。

## 2. P2：恢复基线时清理旧缓存

- [x] **T2：修复统一缓存生命周期并覆盖调用方。** 依赖 T1 完成，避免同时调整同一草稿确认语义。

主要文件：`frontend/src/services/draftSessions.ts`、`frontend/src/services/draftCache.ts`、`frontend/tests/autosave-scope.test.ts`；既有 Narrative/卷测试按发现补充，拆成后续小提交。

实现约定：

- 已有 baseline 且当前值等于它时，取消旧定时器并清理该 scope 的缓存；只在身份和基线明确时执行，避免初始化/恢复期间误删其他草稿。
- 明确缓存删除失败的返回值和提示。内容相等与缓存清理成功是两个状态，不能把删除失败伪装成安全恢复；按需检查删除后读回，并在重新打开时重试。浏览器存储持续不可用的限制明确记录。
- 检查 Canon、Memory、Chapter、Scene、Narrative fact/knowledge、Volume，以及已有自行清缓存的 proposalDraft/正文编辑，避免重复逻辑或恢复 watcher 串写。

验收：

1. 自动保存前撤回、缓存落盘后撤回、A→B→A、刷新重开均保留基线，不复活已撤销文本。
2. 仍有作者修改的缓存不能被清理；缓存写失败/删除失败仍有可辨识状态，不能错误报告暂存成功。
3. 四类原表单使用真实 stores 参数化验证；新增 Narrative/卷调用方分别验证。原 AUD-01/02 的防抖、保存中输入与离开保护回归通过。

验证：虚拟计时器 + localStorage 故障注入；完整前端 test/lint/build。检查点 A：T1/T2 用例从修复前失败转为通过，再开始性能改动。

## 3. 性能定位与改动基线

主要文件：`e2e/longform-benchmark.mjs`、`backend/tests/test_longform_benchmark.py`、`docs/performance/` 下新增结果文件。

沿用 20/200/999 场景及每场景 3 次修订的夹具、协议 2 和相同硬件。开始前保存既有 `.tmp/performance-*` 结果，避免脚本覆盖证据；记录提交号、运行模式、机器、冷启动及预热定义。增加 CDP trace、请求数量/响应字节、DOM 数量、主线程耗时和必要的数据库查询计数。

验收：用同一作者动作分解历史首开、场景切换、项目往返的请求/脚本/layout 成本；记录 5 次样本的中位与最大值并保存全部原始样本。20 秒长尾没有定位前只作为现象，不宣称单一根因。

不在性能测量期间并发跑其他高负载测试。每个优化切片先跑代表档，阶段验收再跑完整三档。

## 4. PERF-01：历史面板按需读取与渲染

- [x] **T4：先限制历史正文 DOM。** 依赖 T3。

主要文件：`frontend/src/components/manuscript/RevisionHistory.vue`、`frontend/src/stores/manuscript/history.ts` 及相应组件测试。

列表初始显示元数据，正文仅在明确展开时挂载；简单折叠但仍保留所有 `<pre>` DOM 不算完成。为当前场景提供明确筛选，同时保留全项目历史入口。比较/恢复按 revision ID 工作，列表变化不能悄悄改选中版本。

验收：初始 DOM 不随所有历史正文字数增长；任意历史版本仍可查看、比较、恢复；加载、失败重试和空状态明确。对比 T3 记录变化，若目标尚未达到继续 T5。

- [x] **T5：根据 profile 缩小历史读取量。** 依赖 T4；若仅 DOM 改动已满足预算且不存在读取瓶颈，记录依据后可不引入分页。

当前依赖：workspace 首次加载直接赋值全量 `manuscriptRevisions`；`revisionCount` 使用数组长度；reviews 经 `ManuscriptRevisionSource` 从数组查来源。不能只把数组换成第一页。

分成两个可独立验证的小切片：

1. 后端新增兼容的历史摘要分页/场景筛选与按 ID 详情读取，先固定稳定排序、总数、页面边界及项目隔离契约。保留旧完整读取行为供现有调用方过渡。沿 router→service/data→repository 边界落地；DTO/API 契约和实现分开提交，避免一次大改。
2. 前端历史列表消费摘要，正文按需读取；同步 workspace 装配、真实总数、比较选择及审核来源按 ID 获取。页面/详情缓存按项目和请求代次隔离；接受、保存、恢复后明确失效。移除作者工作台进入时不必要的全历史正文请求，保留完整导出/备份路径。

建议列表默认 50 条、服务端上限 100，实际响应上限和排序在契约中确定；加载更多或翻页必须让全部历史可达。若新增索引，只依据查询计划并单独验证迁移。

验收：第 1 页及跨页历史无重复/遗漏，计数为总数；未加载页的审核来源和比较/恢复仍可读；首屏请求和 DOM 有明确上界；旧接口、备份恢复和权限隔离不退化。

## 5. PERF-02：减少场景与项目切换工作量

- [x] **T6：优化场景目录的重复扫描。** 依赖 T3、T4/T5 完成后的状态结构。

主要文件：`frontend/src/components/ManuscriptWorkspace.vue`、`frontend/src/domain/manuscriptOrganization.ts` 及组织/目录测试。

依据 trace 和调用计数，把每行 `.some` 扫描改为按 scene ID 的派生 Map/Set，按 chapter ID 预分组，减少切换时无关排序/过滤。派生索引只依赖实际源数据；场景、提案和正文更新后自动失效，不建立另一套可写权威状态。

验收：状态标签、待审数量、规划过期提示、卷/章节归属与搜索排序完全一致；同样操作的主线程工作减少，999 档场景切换中位≤200ms。

- [x] **T7：优化项目进入的非当前面板读取。** 依赖 T6。

主要文件：`frontend/src/stores/workspace.ts`、`frontend/src/stores/manuscript.ts`，以及 profile 命中的领域 store；单个切片控制在约 3–5 个文件。

区分当前编辑必需数据与辅助面板数据。仅对实测阻塞项目进入的 graph/director/progress 等请求采用按需读取、去重或分阶段加载，提供 loading/error/retry。后端查询仅在测量证实后单独优化，缓存必须有明确的变更失效规则。

验收：快速切项目、往返原项目和取消离开均不串状态；辅助请求失败不丢草稿、不伪装成空结果；后台数据最终可达；999 档项目切换往返中位≤2秒，测量必须包括抵达可用编辑状态，不能仅提早关闭 loading 来达标。

检查点 B：历史预算和切换预算分别达标；未达标保留为未完成，并根据 trace 调整方案，不扩大硬上限或缩减夹具。
